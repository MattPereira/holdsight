# Audit history for leaked credentials

Before cutover the private repository's full history was audited for secrets committed then later removed, using two independent methods that agreed on zero findings: gitleaks scanned all 159 reachable commits, and every one of the 1840 git objects (reachable plus dangling) was grepped for the literal values of all 18 real secrets currently in `.env`/`.env.local` (Plaid production, Google OAuth, Zerion, Schwab, the encryption keys, Blob and OIDC tokens). This confirms deleting the old history per ADR-0006 leaves no credential exposure even if a clone survives. Findings were possible because these are high-consequence banking, payment, and brokerage credentials, so the standing policy for any future hit is rotate-always at the provider first — assume compromise regardless of whether the object was ever pushed — then scrub history as cleanup.
